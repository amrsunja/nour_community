## 1. Общее описание

Модуль «Мечети» — двусторонняя платформа внутри приложения Nour:

- **Сторона пользователя:** поиск мечетей (гео + текст), карточка мечети с расписанием молитв, сервисами, анонсами и событиями, подписка на уведомления, донаты (разовые и регулярные), участие в сборах (кампаниях), членство в мечети.
- **Сторона мечети:** полноценная админ-панель — управление профилем, расписанием, сервисами, анонсами, событиями, push-уведомлениями подписчикам, сборами и донатами, списком донатеров и членов, аналитикой.

Финансовая архитектура — **Stripe Connect (direct charges)**: каждая мечеть подключает собственный Stripe-аккаунт, деньги поступают напрямую на счёт мечети. Платформа Nour не хранит, не распределяет и не касается средств — она только обрабатывает данные о транзакциях для статистики и интерфейса. Юридический получатель платежа (merchant of record) — мечеть.

## 2. Функциональный скоуп

### Блок A — Ядро модуля (спецификация V2, раздел 7)

**A1. Поиск мечети**
- Поиск по названию, городу, адресу.
- Режим «рядом со мной»: геолокация + поиск по радиусу (PostGIS).
- Результаты: название, фото, дистанция, рейтинг.
- Выбор 1 основной + 1 вторичной мечети на пользователя.

**A2. Карточка мечети (4 таба)**
- *Инфо:* обложка, логотип, название, адрес (+копирование), кнопка «Маршрут» (открытие карт), телефон (звонок), email, сайт, соцсети, описание, статус Open/Closed, счётчики followers / members.
- *Расписание (Prayers):* 5 ежедневных молитв + расписание Joumou'a.
- *Сервисы:* чеклист из ~11 позиций (женский зал, доступ для инвалидов, парковка, зал омовения, курсы детям/взрослым, курсы Корана, арабский язык, janaza, ифтар Рамадан, библиотека, сопровождение новообращённых).
- *Анонсы и события (News):* активные анонсы; события с кнопкой «Добавить в календарь» — генерация и экспорт .ics файла (без интеграции Google/Apple Calendar).

**A3. Подписка на мечеть (Follow)**
- Кнопки Follow / Unfollow.
- Push-уведомления от мечети подписчикам (требует FCM-инфраструктуру — см. зависимость в разделе 7).

**A4. Админ-панель мечети (табы)**
- *Профиль:* редактирование всех полей, загрузка обложки и логотипа (Supabase Storage).
- *Расписание:* ввод и правка времён молитв и Joumou'a.
- *Сервисы:* чекбоксы доступных сервисов.
- *Анонсы:* создание / правка / удаление, максимум 2 активных.
- *События:* создание / правка / удаление, максимум 3 активных.
- *Уведомления:* отправка push подписчикам, лимит 1–2 в неделю (rate-limit на сервере).
- *Статистика:* число подписчиков, просмотры профиля, open-rate уведомлений.

**A5. Регистрация и верификация мечети** *(скрытый функционал — в спеках отсутствует, но без него модуль не работает)*
- Флоу «Заявить мечеть»: представитель мечети подаёт заявку (данные мечети + подтверждающие документы/контакт).
- Модерация заявок в существующей админ-панели Nour (одобрить / отклонить).
- Роль `mosque_admin`, привязка пользователь → мечеть, RLS-политики на редактирование только своей мечети.
- Возможность нескольких администраторов одной мечети (опционально, +0,5 дня).

### Блок B — Донаты и сборы (по макетам)

**B1. Stripe Connect онбординг мечети**
- Кнопка «Активировать донаты» в админ-панели.
- Создание Express-аккаунта, редирект на Stripe hosted onboarding (KYC, банковские реквизиты — всё проверяет Stripe).
- Обработка webhook `account.updated`; донаты открываются только при `charges_enabled = true`.
- Экран статуса онбординга (не начат / в процессе / активен / требует документов).

**B2. Общий фонд «Sadaqah» (Support the mosque)**
- Постоянный сбор «на нужды мечети» (описание редактируется мечетью).
- Пользователь: выбор типа — **One-time / Monthly / Yearly**, пресеты сумм (10/50/100/150 €) + ручной ввод.
- Оплата через нативный Stripe PaymentSheet: карта, Apple Pay, Google Pay (без webview).
- Recurring: Stripe Subscription на connected-аккаунте мечети; управление своими регулярными донатами (список, отмена) в профиле пользователя.

**B3. Кампании (Fundraising campaigns)**
- Мечеть создаёт целевые сборы: название, описание, фото, цель (€), дедлайн. Лимит активных кампаний (по умолчанию 3).
- Пользователь: карточка кампании — фото, прогресс-бар «собрано / цель», счётчик донатеров, аватары, «осталось N дней», кнопки **Contribute** и **Share** (deep link на кампанию).
- Прогресс обновляется в реальном времени (Supabase Realtime).
- Автозакрытие по дедлайну; статусы: активна / завершена / цель достигнута.

**B4. Членство (Become a member)**
- Анкета: имя, фамилия, дата рождения, профессия, email, телефон, готовность волонтёрить, согласие на обработку данных (GDPR-чекбокс).
- Опциональный годовой взнос: пресеты 60/120/240 € + ручной ввод, либо бесплатное членство.
- Взнос = recurring-подписка (yearly) на аккаунте мечети.
- Счётчик members на карточке мечети; список членов в админ-панели (экспорт CSV).

**B5. Финансовая аналитика мечети (таб Donation в админке)**
- Сводка: собрано за год, динамика vs прошлый год (%), разбивка Support / Campaigns (суммы + %), число донатеров, число recurring-донатеров, средний донат.
- Блок Sadaqah: за месяц, число разовых донатов, число monthly-донатеров.
- Список кампаний с прогрессом + управление (создать / изменить / закрыть).
- **Donors list:** список донатов (донатер — можно анонимно, сумма, дата, тип, кампания), фильтры, экспорт CSV.
- **Tax receipts:** автогенерация PDF-квитанции (реквизиты мечети, донатер, сумма, дата, номер) по каждому донату / годовой сводной; отправка на email донатера. Формат совместим с французским reçu fiscal (CERFA) — юридическая ответственность за право выдачи на мечети (см. раздел 8).

**B6. Серверная платёжная логика**
- Edge functions: создание PaymentIntent / Subscription на connected-аккаунте (сервер валидирует суммы и кампанию — клиент не устанавливает цену), webhook-обработчик (идемпотентный, по образцу существующего `stripe-webhook`), синхронизация статусов recurring.
- Все донаты пишутся в собственную БД → на этом строится вся аналитика.
- Fallback (опция): поле «внешняя ссылка на сборы» для мечетей, отказавшихся от Stripe — кнопка без статистики.

### Изменения существующего

- `profiles`: без изменений (роль мечети — через `mosque_admins`, не через флаг).
- Включение расширения **PostGIS** (гео-поиск по радиусу) — новая зависимость проекта.
- RLS-политики на все новые таблицы: публичное чтение верифицированных мечетей; запись — только админ своей мечети; донаты — донатер видит только свои, мечеть видит свои поступления.
- Триггер `mosque_donations (pending → succeeded)` → инкремент `mosque_campaigns.collected_amount` (по образцу существующего платёжного триггера).
- Таблицы `mosque_campaigns`, `mosque_donations` — в Realtime publication.
- Storage buckets: `mosque-media` (публичный), `mosque-receipts` (приватный).

## 5. Что НЕ входит в данный devis

- Push-инфраструктура FCM как таковая (отдельная позиция общей сметы V2 — €3 000–3 500; модуль мечетей от неё **зависит**).
- Наполнение: данные мечетей, фото, переводы контента.
- Верификация мечетей как операционный процесс (проверку заявок выполняет заказчик; я делаю инструмент).
- Рейтинг/отзывы мечетей (на макетах есть «note» — механика оценок не специфицирована; при необходимости +2–3 дня, +€1 200–1 800).
- Дизайн-макеты (Karim).
- Юридическая валидация reçu fiscal / статусов ассоциаций.
- Мультиязычный контент мечетей (профиль заполняется на одном языке; интерфейс — на 12 языках приложения как обычно).

## 8. Нюансы и риски — для обсуждения с заказчиком

**1. Деньги не проходят через Nour — и это нужно зафиксировать письменно.** Архитектура direct charges означает: получатель платежа — мечеть, KYC делает Stripe, chargebacks и возвраты — зона мечети. Nour — техническая платформа. Это снимает риск, который вас беспокоил, но это же надо отразить в CGU/оферте для мечетей (юрист заказчика).

**2. Reçu fiscal (CERFA).** Право выдавать налоговые квитанции имеют не все ассоциации (различие loi 1901 / 1905, cultuelle vs culturelle). Приложение генерирует PDF от имени мечети; подтверждение права выдачи — чекбокс-декларация мечети при онбординге. Ответственность — на мечети, не на платформе.

**3. App Store / Google Play.** Донаты некоммерческим организациям разрешены вне In-App Purchase (Apple guideline 3.2.2) — комиссии сторов 15–30% на донаты НЕ распространяются. Stripe PaymentSheet легален. При ревью Apple может запросить подтверждение некоммерческого статуса получателей — верификация мечетей (A5) здесь и пригодится.

**4. Комиссии Stripe.** ~1,5–2,5% + 0,25 € с транзакции платит мечеть (вычитается из доната). Recurring-подписки — та же ставка. Стоит показать это мечетям честно на экране онбординга.

**5. Монетизация V3 заложена в архитектуру.** Когда появится «Mosquée Pro», платформенная комиссия добавляется параметром `application_fee_amount` в существующий платёжный вызов — без переделки. Также возможна модель подписки мечети на Pro-функции.

**6. Лимиты уведомлений — серверные.** Rate-limit 1–2 push/неделю enforce'ится в edge function, не в UI, иначе мечети будут спамить и убьют opt-in подписчиков.

**7. Анонимность донатов.** На макетах есть аватары донатеров. Нужна опция «донат анонимно» (в Donors list мечети — «Anonyme», в публичных счётчиках — только число). Заложено в B2.

**8. Спорные заявки на мечеть.** Возможен конфликт «две заявки на одну мечеть» / захват чужой мечети. Процесс верификации (документы, звонок) — операционная задача заказчика; инструмент модерации я предоставляю.

**9. Open-rate уведомлений** (метрика в статистике) требует трекинга открытий пушей — реализуемо через FCM analytics + собственный лог, точность ограничена платформами (iOS не всегда репортит доставку). Метрика будет оценочной — честно указать мечетям.

**10. Vs вариант «webview-ссылки».** Обсуждённая ранее альтернатива (мечеть вставляет Stripe/PayPal-ссылку, оплата в webview) стоила бы €2 000–3 000, но не реализует ничего из макетов: ни прогресс-баров, ни recurring, ни donors list, ни квитанций, ни аналитики — и не даёт пути к монетизации V3.
